PROBLEM
A value is changed somewhere below the surface of an object - an entry inside a list held by a field, a flag on a member of a collection - and nothing on screen moves. Changing anything at the surface of the same object updates immediately, so the report reads as 'deep changes do not refresh'. The opposite report also exists in this folder: a screen that redraws on every tick although nothing a viewer could perceive has altered, because the comparison in play declares two freshly built descriptions of an identical thing to be different. Both come from the same decision - how far a cheap comparison is allowed to look before it commits to an answer - and the libraries here have made that decision differently and in different places. Which files decide how deep the comparison goes, and which own the contract the comparison is supposed to satisfy?
