PROBLEM
Some of these libraries talk to a copy of themselves running somewhere else - another tab, another frame, a browser extension's page half, a server producing a stream for a client to replay. The code that receives one of those messages treats it as though it were an ordinary call made from inside the same program: it applies the payload directly, it lets whatever the application's handlers throw escape into the transport, and it hands the reply back to the platform without ever looking at the promise the platform gave it. So a handler that fails while applying an incoming message leaves the receiving side wedged part-way through the change it was making, and a delivery that the platform rejects disappears entirely - nothing is retried, nothing is logged, and the two sides quietly stop agreeing. The contract is that the far side is not trusted, not synchronous and not guaranteed: every message has to be validated as data, every application of it has to be contained so a failure cannot corrupt the receiver's own state, and every send has to have its outcome observed. Elsewhere in the folder the same channel is handled as a real boundary: one library checks the sender and the shape of every inbound event before it looks at the contents, another routes failures that would otherwise vanish into an explicit channel of their own, another splits an oversized payload into pieces small enough that the transport cannot refuse them and reassembles them on arrival, and another turns a failure on the producing side into a value the consuming side can see rather than an exception thrown into a socket. Which file applies a foreign message as though it were a local call, and which own the boundary contract it has to be brought in line with?
